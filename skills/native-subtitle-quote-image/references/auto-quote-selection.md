# 自动选句与批量出图

解决一个具体瓶颈：用户想截「最精彩的几句」，但要挑出这几句就得把整期视频看完。
本流程把「阶段 4：用文字稿选题」自动化，让用户只需在几十条候选里做取舍。

前提是**已经有带时间戳的文字稿**。文字稿从哪来，见
[yt-dlp-and-transcripts.md](yt-dlp-and-transcripts.md)（YouTube / 本地 Whisper）或
[cn-platforms.md](cn-platforms.md)（国内平台）。

## 一句话流程

```bash
python3 "<SKILL_DIR>/scripts/select_quotes.py" pick TRANSCRIPT.json \
  --out OUT_DIR --top 5

# 或整库批处理
python3 "<SKILL_DIR>/scripts/select_quotes.py" batch TRANSCRIPT_ROOT \
  --out OUT_DIR --top 5
```

`TRANSCRIPT` 支持 `.transcript.json`（faster-whisper / openai-whisper 的 `segments` 结构）、
普通 `.json`（数组或带 `segments` 的对象）、`.srt`。
**纯 `.txt` 会被拒绝**——没有时间戳就无法定位取帧点。
给了 `--video` 时用 FFmpeg 读真实时长来校正清洗边界，没给则用文字稿自带 `duration`。

产出（每期视频一个目录）：

| 文件 | 用途 |
|---|---|
| `审阅表.md` | **给人看的**。逐条候选的起止、六维打分、信号词、逐行原文 |
| `candidates.json` | 全部候选窗口与打分，供模型复排 |
| `native_manifest.json` | 原生字幕模式，直接喂 `render --manifest` |
| `script_lines.json` | 脚本字幕模式的索引（数组） |
| `scripts/NN_标题.json` | 脚本字幕模式真正要喂的文件，**一张图一个** |
| `渲染脚本字幕.sh` | 生成好的渲染命令，改好 `VIDEO` 即可跑 |

批处理额外产出 `全局精选.md` / `全局精选.json`：跨所有视频的总分排序。

## 为什么不能直接用模型读整篇文字稿

一期 6–28 分钟的中文长视频，转写后有 100–1200 段、几千到上万字。一批几十期就是几十万字。
确定性清洗先做三件事，把模型的工作量压到可承受：

1. **砍掉不可能入选的段**（片尾套话、幻觉段、重复段、空段）；
2. **切成固定粒度的候选窗口**并打分排序；
3. **去重**，避免几张图讲同一件事。

模型只在最后一步介入：读 `审阅表.md`，判断语义是否真的成立、改写标题、定终选。
`select_quotes.py` **不声称自己懂语义**，`审阅表.md` 也把这句话写在末尾。

## 实测数据（59 期抖音知识类视频，568 分钟）

```
覆盖视频     59（1 期被拒：音乐歌单，清洗后仅剩 2 段）
候选窗口     50,557
入选         291
耗时         约 4 秒
```

从 50,557 个窗口压到 291 条，压缩比约 174:1。

## 三个必须知道的数据事实

这些是实测结论，直接决定了流程为什么长这样。

### 1. 中文长视频转写**没有标点**

59 期里 **56 期完全没有标点**。所以**不能靠标点切句**。

### 2. 转写段之间**几乎没有停顿**

段间停顿时长中位数 **0.00 秒**，停顿超过 0.5 秒的只有 **1/648 处**。
所以**也不能靠停顿切句**。

结论：原始段本身就是唯一的可靠单位。好消息是它天然合格——
段字数中位 **14 字**、段时长中位 **2.52 秒**，正好是字幕行的粒度。
所以 `select_quotes.py` 不切句：**一句引文 = 连续 N 个原始段**。
这也让取帧时间点天然等于段中点，不需要再合成时间。

### 3. 末段幻觉会超出视频总时长

**11/59 期**的末段 `end` 比视频总时长多出几十秒，典型形态是
`[217.70 → 247.68] 感谢观看`（总时长 217.73 秒）。

不处理就会踩到渲染器的硬校验：`times[-1]` 或 `lines[i].t` 一旦 `>= duration`
就直接报错退出。`sanitize()` 用三条独立规则兜底：

- `start` 越过总时长 → 整段丢弃；
- `end` 越过总时长 → 截到总时长；
- 单段跨度 > 20 秒（静音幻觉的典型形态）→ 丢弃。

注意：这类幻觉段的 `start` 往往**刚好卡在总时长以内**（217.70 < 217.73），
所以真正命中的通常是套话规则或跨度规则。「超出总时长」那条是兜底，不是主力。

## 六维打分

沿用 [end-to-end-workflow.md](end-to-end-workflow.md) 的候选主题评分维度，
把其中四个可计算的做成公式：

| 维度 | 权重 | 怎么算 |
|---|---|---|
| 发布价值 | 0.50 | 信号词累加：数量 / 反常识 / 因果 / 结论 / 行动建议 / 定义 |
| 独立性 | 0.20 | 首行不悬空 + 首行够长 + 中后段无话题推进标记 |
| 连续性 | 0.15 | 句数 4–6、时间跨度 8–40 秒、相邻行词面重叠 |
| 信息密度 | 0.15 | 填充词占比、二字词去重率，再乘开场铺垫阻尼 |
| 画面可用性 | — | 无视频时标 `unknown`，不参与计算 |
| 真实性 | 门禁 | 逐字取自转写，不做加权 |

### 信号词表里的一个坑

「数量」信号**绝不能把「第一」「第二个」算成数字**。
中文里序数词无处不在，实测会把过半候选都误标成「数字」，直接毁掉排序。
只认：阿拉伯数字带单位（`500万`、`一个月`、`2023年`）、`百分之X`、中文数词带量级单位（`三倍`）。

回归测试 `test_ordinals_are_not_counted_as_quantity` 守着这条，并做过反向验证。

### 开场铺垫

「今天我们来聊聊」「希望大家耐心听完」「先交代一下背景」这类行信息量低，
但不直接丢弃——**有的视频第一句就是论点**。做法是给密度和价值乘一个阻尼系数
（`max(0.35, 1 - 铺垫数 × 0.3)`），让它自然沉底。

## 去重

两道，缺一不可：

1. **共享行数比例 ≥ 0.34** 的两个窗口不能同时入选；
2. **起始行索引相距 < 3** 的两个窗口不能同时入选。

只靠时间重叠不够：实测两个窗口可以在时间上只压边、却共享大部分行，
两个都会被选中，最后交付两张讲同一件事的图。

## 输出格式的两个硬约束

### 脚本字幕模式必须一张图一个文件

`render-script` 的 `--script` 接的是**单个** `{"lines": [...]}`，不是数组。
把多张图塞成一个数组会直接报「台词脚本必须包含至少 2 项的 lines 数组」。
所以 `scripts/` 目录下一张图一个文件，配一个 `渲染脚本字幕.sh` 循环调用。

原生字幕模式相反：`render` 的 `--manifest` 本身就接受多张图，汇总成一个 JSON 即可。

### 窗口有几行就取几个时间点

**绝不能为了凑固定的 5 个而均匀抽稀。**实测踩过：6 行抽 5 个，
恰好丢掉「这种逆差在正常情况下会导致货币贬值和经济困难」这一环，
图上论证链直接断掉。窗口本身只有 4–6 行，都在 `MAX_TIMES_PER_IMAGE = 7` 之内。

## 竖屏素材：脚本模式的重影

脚本字幕模式把台词画到画面上时，如果源视频**本来就有烧录字幕**，
默认 `--band-center 0.88` 会和原字幕叠在一起，出图出现重影。

实测有效的做法是先把原字幕区域裁掉：

```bash
python3 "<SKILL_DIR>/scripts/native_subtitle_stitch.py" render-script VIDEO \
  --script scripts/01_xxx.json --out out/01.jpg \
  --aspect 9:16 --width 1080 \
  --frame-bottom 0.55 --band-center 0.5
```

`--band-center` 是相对**裁切之后**的画面，所以裁到 0.55 后要用 0.5 重新居中。
详见 [portrait-and-vertical.md](portrait-and-vertical.md)。

> 如果源视频本来就有你需要的烧录字幕，**优先走原生字幕模式**——
> 不画字、不需要校对、像素可回溯，是更省事也更忠实的选择。
> 脚本模式留给「没有字幕」或「需要换成译文/改写台词」的场景。

## 转写错字必须先校对

实测样本里的错字：`约数条件` 应为 `约束条件`、`AHM经理` 应为 `AI产品经理`、
`消费战胜的意识形态` 应为 `消费战胜了意识形态`、`强盗` 应为 `强调`。

- **原生字幕模式**：错字在画面像素里，我们不重绘，不需要处理；
  但 `审阅表.md` 的原文会带错字，**引用时不要照抄**。
- **脚本字幕模式**：错字会直接画进图，**必须先校对**。

## 交付前必须做的三件事

1. **打开 `审阅表.md` 逐条看**，删掉语义不成立的候选，改写标题。
2. **生成图片后逐张打开检查**（见 [end-to-end-workflow.md](end-to-end-workflow.md) 阶段 9）。
   `select_quotes.py` 只保证「时间点合法、画面不重复」，不保证「这一句值得发」。
3. **交付时说明**：哪些图的时间点是自动选的、候选是否经用户确认。
   不要把自动排序的结果直接当作「已确认值得发布」。

## 局限（写清楚，不掩饰）

- 打分是**形式特征**：信号词、词面重叠、句数、跨度。它认得出「像金句」的结构，
  认不出反讽、上下文依赖和圈内梗。
- `画面可用性` 无视频时为 `unknown`，所以**选出的时间点可能落在人物闭眼或转场帧上**，
  必须靠 `sample` 回看。
- 词面重叠只能近似连贯性。没有标点和停顿可用时，跨话题的窗口无法完全避免。
- 不接受「让模型直接读整篇文字稿自由发挥」的做法：批处理跑不动，
  且失去逐句回溯到原视频的能力。
