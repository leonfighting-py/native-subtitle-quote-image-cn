# 紧凑型视频字幕拼图视觉规范

当用户强调“好看、紧凑、有节奏、不要台词间隔太宽”，或准备最终视觉质检时读取本文件。规则同时适用于原生字幕和脚本字幕模式；只有脚本模式会绘制字体和描边，原生模式始终保留视频像素。本规范来自对高质量成品的版式测量与视觉归纳；参考原图不随 Skill 分发。

## 核心判断

3:4 拼图的视觉中心应是主画面，而不是平均分配的五块视频截图。字幕条只承担连续阅读，不应因为台词少而被拉成大块画面。

默认目标：

- 原生字幕默认按源画面和字幕条计算高度，不强制 3:4；显式要求固定比例时，默认对整张拼图统一裁去两侧（`--fit crop`），最多裁到字幕安全边界，剩余差额再留边；不分别填满主图和字幕条。
- 脚本字幕固定画布为 3:4；推荐输出 1440×1920，1080×1440 也符合比例。
- 一张图使用 5 个时间点：1 个主画面 + 4 个字幕条。
- 脚本固定布局的 4 个字幕条时，主画面约占总高度 70%，每个字幕条约占 7.5%。原生模式优先保证所有字幕同一缩放倍数，不套用此比例。
- 字幕条首尾直接相接，条间距为 0，不增加边框、留白或装饰分隔线。
- 原生模式的单行字幕默认从源画面的 `0.78–0.96` 高度范围裁切；字幕偏高或两行时再扩大。

## 原比例布局

用户要求保留横屏构图或原始画面尺寸时，用 `--layout natural`，而不是强制把画面填进 3:4。主图与字幕条只裁切、等比缩放，最终高度为各块实际高度之和；不传 `--width` 时保留源宽度。原生字幕保留到 `--band-bottom` 的主图；脚本字幕默认保留全帧，可按实测边界用 `--frame-top` / `--frame-bottom` 裁去源字幕等区域。`--band-center` 相对裁切后的画面。

裁去底部 28% 后，剩余画面高度就是原高的 72%，不能再拉回原高。最后也不能用直接 resize 强制输出 3:4；确实需要固定比例时回到固定布局重新渲染。画面原比例与“原生字幕”是不同概念，不改变字幕模式。

下面的密度计算和 68–72% 验收仅适用于脚本固定布局；原生模式及原比例布局检查主体几何、文字完整及紧凑拼接，不追求同一个高度比例。

## 自适应密度

脚本固定布局默认按字幕条数量自动计算主画面比例：

```text
主画面比例 = clamp(1 - 字幕条数量 × 0.075, 0.48, 0.82)
```

常见结果：

| 时间点 | 字幕条 | 主画面比例 | 视觉效果 |
|---:|---:|---:|---|
| 3 | 2 | 82% | 少量台词时保留大主图，不拉高字幕条 |
| 4 | 3 | 77.5% | 适合短观点 |
| 5 | 4 | 70% | 默认、最均衡 |
| 6 | 5 | 62.5% | 信息较多，仍保持紧凑 |
| 7 | 6 | 55% | 接近密度上限，需要重点检查字号与可读性 |

用户明确传入 `--hero-fraction` 时尊重用户值。只有实际版式需要时才覆盖自动值，不要为了“更满”而把主图压得过小。

原生固定布局的此参数仅调整源主图的裁切高度，受可用源像素限制；不能分别缩放主图和字幕条以达成目标比例。原生字幕不重绘、不人为统一原视频中本就不同的字号。

## 字幕区域

### 单行字幕

从 `--band-top 0.78 --band-bottom 0.96` 开始预览。目标是：

- 保留完整文字、描边和标点；
- 字幕上下有少量呼吸空间，但不会出现大块无文字背景；
- 缩放到最终条高后仍然清楚；
- 不切进播放器进度条或画面底部黑边。

### 两行字幕或位置偏高

不要继续使用窄裁切硬切第二行。先通过 `band` 预览，再按实际位置扩大，例如 `0.62–0.96` 或 `0.68–0.97`。两行字幕会提高字幕条本身的信息密度，需要检查是否仍适合 4 条拼接。

### 字幕位置变化

同一视频至少抽查开头、中段、结尾。若节目在不同段落改变字幕位置，不能只用一张预览推断整期；换片段或为不同组分别渲染。

## 主画面选择

主画面承担第一眼吸引力，优先级高于第一句文字是否最完整：

1. 主体面部、手势或关键物体清楚；
2. 人物不闭眼、不处于口型或动作的尴尬过渡；
3. 麦克风、前景物体和画面边缘不异常切断主体；
4. 背景明暗和主体分离，字幕描边能够读清；
5. 第一条字幕位于画面下部，不压脸、不贴底；
6. 避免转场、黑帧、广告、播放器控件、通知和无关 UI。

主画面可以与后续字幕条来自同一场景，但帧本身必须比普通字幕条更完整、更有表现力。

### 主画面选帧（脚本固定布局默认开启）

脚本固定布局下，`render-script` 不再机械地取第一句时间点那一帧当主画面：
如果那一帧是幻灯片 / 纯色卡片，或画面里没人，它会在**第一句台词前后 `--hero-search` 秒（默认 1.5 秒）**内就近换一帧。判定顺序：

1. 第一句那一帧里本来就有人 → 原样保留（不会因为「旁边那帧更好看」而乱换）；
2. 窗口内有人 → 取离第一句最近的那一帧；
3. 窗口内都没人、第一句那一帧是纯色 / 近白卡片 → 取最近的「不是卡片」的一帧；
4. 都不满足 → 回退到第一句那一帧。

「有人」用肤色像素占比判断（YCbCr：Cb 77–127、Cr 133–173，且 `r > 60`）；
「纯色 / 近白卡片」用近白像素占比 ≥ 40% 或量化颜色数 ≤ 12 判断。两个阈值都来自实测：
TED 类访谈里人像镜头肤色占比 3.6%–5.3%、近白占比 0.000%、颜色数 35–41；白底幻灯片肤色占比
0.000%、近白占比 44%–58%、颜色数 11。全程不需要模型、不需要联网，也不读任何内容语义。

命令行会打印实际选择，便于复核：

```text
主画面: 主画面改用 4.88s 的那一帧（首句那一帧里没有人，向后找了 0.75s）
主画面: 沿用首句 20.38s 的那一帧（画面里有人）
```

边界：

- 这套判断只认「肤色像素」，木质、米色、暖色调背景可能被误判成「有人」。因此它只在 ±1.5 秒
  内作用，误判的影响被限制在邻近帧；换来的帧仍然贴着第一句台词。
- 选帧只动主画面，字幕条仍然取各自时间点的原始画面。
- `--hero-search 0` 关闭选帧，固定用第一句那一帧。
- `--layout natural` 不接受 `--hero-search`：原比例布局的帧自带烧录字幕，必须与时间点对齐。

## 字幕条节奏

- 四条字幕应像连续段落，而不是四张独立海报。
- 每条只保留一个稳定字幕单位；不要在一条里留下上一句残影。
- 相邻字幕语义递进，避免同义重复和长铺垫。
- 背景变化可以增加节奏，但不能以字幕难读、人物异常或画面杂乱为代价。
- 明暗差异很大的条可以保留，这是原视频真实画面；不要额外加纯色背景统一它们。
- 原生模式不重新绘字、不改字体、不人为增加行距，不用文章标题替换视频字幕。
- 脚本模式使用已审核单行台词，白字黑边、水平居中；字号过小时拆句，不通过放大字幕条来补救。

## 常见失败及修正

| 现象 | 原因 | 修正 |
|---|---|---|
| 台词之间像隔着大段空白 | 主图比例固定过小，少量字幕条被平均拉高 | 使用自动主图比例，不显式传过小的 `--hero-fraction` |
| 每条字幕上下背景太多 | 字幕裁切区域过高 | 单行字幕从 `0.78–0.96` 重新预览 |
| 第一条字幕很大，后续字幕很小 | 主图与字幕条分别填满不同形状的区域 | 先拼源像素，再整图统一缩放；原生模式不用 70% 硬填主图 |
| 字幕条之间有黑缝或白缝 | 额外边距、画布未贴合或源黑边被裁入 | 条间距保持 0，并收紧字幕区域 |
| 文字被切边 | 为追求紧凑直接套用窄裁切 | 以完整字幕为硬条件，扩大 `band` 后重新预览 |
| 主画面是一张写着大字的幻灯片 | 第一句时间点正好落在图表或幻灯片上 | 脚本固定布局默认按 `--hero-search 1.5` 就近换帧并打印选择；仍不满意就打开 `--hero-search` 加大半径，或按「主画面选择」用 `sample` 重挑时间点 |
| 固定 3:4 上下黑边很厚 | 横屏拼图比 3:4 宽，又用了纯留边 | 保持默认 `--fit crop`；字幕太宽裁不动时，减少过宽的句子或接受部分留边 |
| 两侧裁切切到人物 | 主体偏离画面中心 | 用 `--crop-center` 把裁切窗口移向人物；仍不行时改用 `--fit pad` |
| 五句话不连贯 | 只按画面挑帧，没有先做语义选段 | 回到文字稿重选连续表达，不靠换帧硬拼 |
| 主图人物被切脸 | 时间点或裁切窗口不合适 | 只换第一时间点，必要时调整主图比例 |

## 最终视觉验收

交付前在原尺寸和缩略总览两个尺度检查：

- 缩略图中主画面明显占主导，四条字幕形成紧凑节奏；
- 原尺寸中每个字、描边和标点完整；
- 脚本固定布局主画面约 68–72%、字幕条合计约 28–32%（默认 4 条时）；原生模式检查同源字号没有因各块缩放而变大变小；
- 条与条之间没有额外像素间距；原生固定画布为保留完整内容而出现的外侧留边不算条间距；
- 没有一条因为无文字背景过多而显得“松”；
- 没有为了紧凑牺牲两行字幕完整性；
- 原生模式的台词都来自真实视频像素；脚本模式的台词与已审核 JSON 一致；两者时间顺序都正确；
- 若成品仍显得松散，先收紧 `band`，再检查时间点数量，最后才手动调整主图比例。
